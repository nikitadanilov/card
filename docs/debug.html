Debugging and caveats

When card finds an error in the input, it reports the location of the problem and stops:

$ ./card notes.deck
notes.deck:12: link ". "Hugo" -> !hugo-top" refers to unknown identifier "hugo-top".

Many inconsistencies, however, do not stop card: a link whose regular expression matches nothing is silently not rendered, and a misspelled URL produces a broken hyperlink. To find them, check the deck:

$ ./card --check self.conf self.deck

With --check (or -c), card builds the deck in a temporary directory, leaving the output directory alone, and reports the problems it finds, each with its location:

– errors in the input that stop card;

– link and note regular expressions that match nothing (an automatic link defined on the deck or a card is reported only if it matches nothing at all);

– hyperlinks and images referring to files that do not exist in the output directory;

– external URLs (of links and images) that do not exist. Each page is requested once, with a HEAD request falling back to GET. A missing page (an HTTP error 4xx) is an error, while a server error or a network failure, which can be transient, is a warning. If a URL has a fragment ("page#name"), the page is fetched with GET and the fragment must be the id or name of an element of the page (text fragments, "#:~:text=...", are not checked). --offline skips this check;

– formulae that TeX does not accept. If pdflatex (or latex) is installed, each card's formulae, display and inline, are typeset together with its TeX definitions in a LaTeX document with the amsmath, amssymb and amscd packages. Without TeX, only braces, environments and \left and \right are checked. MathJax and LaTeX are not identical, so an occasional formula can be accepted by one and rejected by the other;

– generated HTML that is not well-formed, such as nested hyperlinks;

– warnings: list attributes set without +, identifiers with spaces, cards overwriting each other's output files, numeric series positions of different lengths and timeline positions that do not start with a date.

The exit status is 1 if there are errors and 0 otherwise. The following tools help to find the cause of a problem.

– -v prints the internal representation of the deck: all nodes with their attributes, layout commands and text. It is printed after the output has been generated, so it shows nothing if card fails.

– The DEBUG attribute enables debugging output for the node on which it is set: level 2 traces matching of the regular expressions, level 3 traces it in more detail, level 4 traces setting of attributes. For example, to debug the styles of a single paragraph, add / DEBUG 3 to it. DEBUG is not inherited: setting it on the deck does not trace the fragments. Level 4 reports only the attributes set after the DEBUG line itself.

– frag.id.show shows the fragment identifiers (see Identifiers).

card comes with a test suite, which is run from the top directory of the repository:

$ python3 -m unittest discover -s tests

Common errors and known limitations:

– A fragment attribute while no fragment is open. This usually happens when a / line follows an empty line, which has already closed the fragment, and also at the start of a card. A : line not immediately following a note line is reported similarly.

– An attribute line without a value, including a code line like "// note" that was not protected by |.

– A list attribute set without +: no error (only a warning from --check), but the value is split into characters. A +key after a plain key is an error. See Attributes.

– Unexpected empty cards. A cardfile without explicit \ lines still forms a card, so a configuration file containing only deck attributes produces an empty card (and an HTML file) of its own. Similarly, a \ line at the very beginning or the very end of a cardfile creates an extra empty card.

– A card without an id in a cardfile given with a directory part (for example, "../notes/a.deck"): the identifier, and hence the output file name, includes the directory, and card fails to create the file. Give such cards explicit identifiers, or run card from the directory of the cardfiles.

– A link is rendered only at its span ends, so at least one end must be a span. A link whose source is a whole node (without a regular expression) is silently ignored. A link from a span to a whole node (a card, a fragment or a note) is a hyperlink to the anchor of the node.

– Only cards can be tagged and placed in series.

– Empty matches of regular expressions (of links, notes and styles) are ignored: "x*" decorates only non-empty runs of "x".

– A card in the "timeline" series requires the deck.url deck attribute.
