Getting started

card is a single Python script. Its only dependency outside of the standard library is the typeguard package, which checks type annotations at run-time. Its current release needs Python 3.9 or later:

$ pip install typeguard
$ git clone https://github.com/nikitadanilov/card
$ cd card

card is invoked with a list of cardfiles. All files are read in the order given and together form a single deck:

$ ./card [-v] FILE...

The only option, -v (or --verbose), prints the internal representation of the deck after the output has been generated (see Debugging and caveats).

Let us write a first deck. Put the following into a file called hello.deck:

/// dir out
// name Hello
// id hello
Hello, world! This is a _very_ short deck.
/ += . "world" -> https://en.wikipedia.org/wiki/Earth

; code
print("Hello, world!")

and run

$ ./card hello.deck

The first line is a deck attribute, telling card to put the output into the "out" directory (the default is "html_out"). The next two lines are attributes of the (only) card: its title and its identifier. Then comes a paragraph with a link attached to the word "world", followed by a code display. The output directory now contains hello.html with the rendered card and the style sheet style.css (see HTML output).

Note that "_very_" was not italicised: conventions such as underscores for italics are not built in; they have to be defined as styles (see Styles). The usual way to do this is to keep the deck-wide definitions (styles, CSS, automatic links) in a separate configuration cardfile that is given to card before the content. This manual is built by

$ ./card self.conf self.deck

where self.conf contains the style definitions and self.deck contains the text. Have a look at both files: they are the most complete example of card usage.

If the deck is going to be published, also set the deck.url deck attribute to the URL of the output directory. Only then does card generate the RSS feed feed.xml and refer to it from every page.
