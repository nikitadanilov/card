Links

A link connects two places: the source and the target. Links are added by += attributes. A link attribute value has the following grammar:

LINK           ::= SOURCE '->' TARGET
SOURCE, TARGET ::= URL | DECK_LOCATION
DECK_LOCATION  ::= NODE [SPAN]
NODE           ::= '.' | '!' IDENTIFIER
SPAN           ::= '"' REGEX '"'

. refers to the current node: the fragment to which the attribute is attached. ! IDENTIFIER refers to the node with the given identifier (see Identifiers). A span is a regular expression (in Python syntax) that selects a part of the text of the node. Anything that does not start with . or ! is a URL. Examples:

\
// id CARD0

Add a link to a web-page here ...
/ id PARA0
/ += . "here" -> https://www.example.com

Another paragraph. Link _to_ it from a particular text in the previous paragraph.
/ += !CARD0-PARA0 "a link" -> . "Link"

When a span is the source of a link (i.e., when it is on the left-hand side of ->), the HTML engine turns the matched text into a hyperlink, like here. When a span is the target of a link, the matched text is underlined and a numbered marginal mark linking back to the source is inserted on the left. If the target is a node without a span, the hyperlink leads to the node's anchor.

The regular expression is matched against the text of the fragment as it is written in the cardfile, before styles are applied, so the source markup characters (like underscores and asterisks) are visible to it. Every match of the expression gets the link, so make the expression specific enough. Use lookaheads and lookbehinds to select a word in a particular context, as in the "EVCOMB(?=:)" example on the Syntax card. Remember that the lines of a paragraph are joined with a space, but leading blanks are preserved: use \s+ rather than a single space to match words that can be split across lines.

The URL can refer to the named groups of the expression at the other end with Python format syntax. Together with the inheritance of links, this gives automatic links. A link attribute set on a card applies to every fragment of the card, and one set on the deck applies to every fragment of the deck. This manual's self.conf contains:

/// += . "(?P<type>str|dict|set|list)\.(?P<func>[a-z.A-Z_0-9]+)\(\)" -> https://docs.python.org/3/library/stdtypes.html#{type}.{func}
/// += . "\bcard\.(?P<code>[a-z.A-Z_0-9]+)\(\)" -> https://raw.githubusercontent.com/nikitadanilov/card/refs/heads/master/card#:~:text={code}

which is how the mentions of str.split() and card.compile_deck() get their hyperlinks. Because the URL of a link with a span at the other end always goes through Python formatting, literal braces in such a URL must be doubled: write "{{" and "}}" for "{" and "}". Otherwise card fails with a KeyError (or IndexError, or ValueError).

The link attribute does not have to be attached to either end of the link. For example, the following attribute, attached to some fragment, links a word in the fragment with identifier "phases-syntax" to a word in the attached fragment:

/ += !phases-syntax "sentences" -> . "marginalia"

This works on a fragment, but not on a card or the deck. A link set on a card or the deck is created anew for every fragment and note below it. That is what makes automatic links with . work, but a link with an explicit "!" end set on a card produces as many copies of the same link as the card has fragments and notes. Put such links on a fragment.

Note that the source end of a link (the regular expression or the URL) cannot contain "->", and identifiers cannot contain spaces.
