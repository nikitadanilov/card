Series and tags

Cards are organised in two ways: by series and by tags.

A series is an ordered sequence of cards. A card is placed in a series by the # attribute, whose value is the name of the series and the position of the card in it:

// +# trunk 07
// +# chrono 2025/04/01

A card can be in any number of series, but only once in each. Positions within a series must be unique and are compared as strings, so use zero-padded numbers ("07", not "7") or ISO dates. If the position is omitted, the identifier of the card is used.

The footer of each card links it to the previous and the following cards in each series the card belongs to, and to the index of the series. For each series, the HTML engine generates an index file, listing all the cards in the series with their titles, briefs and tags. The brief is cut to its first 80 characters, so keep brief attributes short. The index comes in several variants (compact or full, in direct or reverse order, as a table or "flat", that is, with the full text of all cards), and each variant links to the others.

Tags are keywords. A card is tagged with the tags attribute:

// +tags concepts
// +tags syntax

For each tag, the HTML engine generates an index file listing the tagged cards.

The series named "timeline" is special: it is used to produce the RSS feed. Each card in this series becomes an item in feed.xml, and the first ten characters of the position are used as the publication date. Use positions like "2025-04-01" or "2025-04-01 12:30" for timeline cards and set the deck.url deck attribute. Note that the date is written to the feed as is, not in the RFC 822 format required by RSS, so some feed readers may reject the feed.
