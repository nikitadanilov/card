Styles

card has no built-in inline markup. Instead, styles are defined by attributes, whose values are regular expressions. The following styles are available:

em: emphasis. it: italics. bd: bold. un: underline. cd: inline code. ma: inline mathematics (see Mathematics). al, ar, ac: align the text to the left, right or centre.

The regular expression must contain two named groups: open and close. The text matched by these groups is removed from the output, and the text between them is rendered in the style. This manual uses (in self.conf)

/// +it (^|[ ])(?P<open>_)[^_]*(?P<close>_)
/// +em (^|[ ])(?P<open>\*)[^*]*(?P<close>\*)
/// +un (^|[ ])(?P<open>-)[^-]*(?P<close>-)
/// +cd (^|[ ])(?P<open>`)[^`]*(?P<close>`)

so that underscores make italics, asterisks make emphasis and so on. The groups can be empty, in which case nothing is removed and the matched text is simply styled. This is used to italicise Latin abbreviations and to typeset anything that looks like a function call as code:

/// +cd (^|[ ])(?P<open>)[a-zA-Z0-9_.:]+\(\)(?P<close>)(?=[- .;!?]|$)
/// +it (?P<open>)e\.g\.(?P<close>)(?=, )

Styles are inherited, so a style can be defined for the whole deck, for a card or for a single fragment. Styles are applied to paragraphs and notes only, not to code, math or headings.

Styles are applied in a fixed order: em, it, bd, un, cd, ma, then the alignments; within one style, the expressions are tried in the order of their definition, the most specific node first. Once a style removes its markers, the later styles no longer see them, so if two styles use the same characters, only the first one has any effect.

Be careful with the expressions: they are applied to the whole paragraph text. With the definitions above, a dash at the beginning of a word starts an underlined span that ends at the next dash in the paragraph. This is why this manual uses en dashes (–) for its lists.
