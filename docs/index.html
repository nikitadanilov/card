Overview

This is the user manual for the card tool.

card is similar to other "publishing" tools that take as the input content marked up with formatting instructions and render it in one or more output formats. It is much simpler than hugo or pandoc and its intended scope is more of a component in a note-taking system than a full-blown site publishing engine.

The input is a "deck", which is a set of "cards", each consisting of "fragments". Fragments correspond to paragraphs and things like code and math displays in the output. Cards are used to organise content into "series"; they can correspond to pages in the output, but not necessarily.

Decks, cards and fragments all have attributes. Attributes are the only mechanism by which formatting is specified: there is no inline markup language built into card. Even the conventional italics and emphasis in this manual are produced by regular expressions defined as attributes of the deck.

Markup instructions are not embedded in the text. For example, the link to Hugo's website above is created by

/ += . "hugo" -> https://gohugo.io/

This attaches the hyperlink to the part of the preceding paragraph matching the regular expression "hugo". The separation between the text and the markup makes (in my personal opinion, that is) the content source more readable.

The documentation is, naturally, maintained via card here. This is how the beginning of this card looks in the source (this is not a Quine preceded by its own quotation):

// C card self-documentation deck: the card user manual.
// name Overview
// id index
// brief What card is, the main concepts and the table of contents.
// +# trunk 00
// +tags concepts
/// deck.title card user manual
/// deck.description The user manual for the card publishing tool.
This is the user manual for the card tool.
/ id top
/ += . "card" -> https://github.com/nikitadanilov/card

The manual consists of the following cards. They form the "trunk" series, so you can also read them in order by following the arrows at the bottom of each card.

– Getting started: installation, running card and a first deck.

– Syntax: the line-oriented format of cardfiles.

– Fragments: paragraphs, code, math, headings and images.

– Attributes: how attributes work, and a reference of attributes understood by card.

– Identifiers: how nodes are named and how to refer to them.

– Links: hyperlinks between the deck and the outside world and within the deck.

– Notes: marginal notes attached to a part of the text.

– Styles: italics, emphasis, code and friends, defined by regular expressions.

– Series and tags: organising cards: series, navigation, indices and the RSS feed.

– Mathematics: inline and display formulae.

– HTML output: the files produced and how to customise them.

– Processing phases: what happens inside card between the input and the output.

– Debugging and caveats: what to do when things go wrong, and known limitations.
